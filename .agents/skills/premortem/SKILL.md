# /premortem — упреждающий разбор провала

Цель: до реализации найти, как решение убьёт проект, и решить — делать, переделать или отказаться. Код НЕ пишется, только анализ + вердикт.

## Workflow (10 шагов с RPN-скорингом)

1. **Зафиксируй решение** одной фразой: что именно собираемся сделать.
2. **Перенесись в будущее:** «прошло 6–12 месяцев, это решение обернулось провалом».
3. **Список причин провала** — минимум 6–8 конкретных сценариев (технических, безопасности, эксплуатации, бизнес).
4. Для каждой причины оцени по 1–10: **Severity** (тяжесть), **Occurrence** (вероятность), **Detection** (насколько трудно заметить заранее; 10 = почти не заметишь).
5. **RPN = S × O × D** для каждой причины.
6. **Отсортируй** по убыванию RPN — верхние 3 это то, что реально убьёт.
7. Для топ-причин — **митигация**: что добавить/изменить в плане, чтобы сбить RPN.
8. **Особый фокус** (под профиль проекта): multi-tenant изоляция, секреты, fail-closed, rate-limit, обратимость миграций, приватность данных.
9. **Пересчитай RPN** после митигаций — стало ли приемлемо.
10. **Вердикт:** GO / GO-с-условиями / REWORK / NO-GO + 1–2 строки обоснования.

## Правила
- Не предлагай реализацию внутри premortem — это отдельный шаг после вердикта.
- Будь конкретен: «refresh_token гонка при 2 воркерах» вместо «могут быть баги».
- Если всплыло >= 2 равных подхода — предложи `/split-decision`; если хочется второго мнения — `/contrarian`.
