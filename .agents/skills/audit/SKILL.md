# /audit — security + privacy ревизия

Цель: до деплоя/модерации найти утечки, дыры изоляции и нарушения приватности. Только чтение + отчёт, правки — отдельным согласованным шагом.

## Чеклист

**Multi-tenant изоляция (Critical):**
- Каждый SQL фильтруется по тенанту (`member_id`) — в `WHERE` или через PK. Найди запросы без фильтра.
- Файлы/артефакты разложены по namespace тенанта (`var/exports/{member_id}/`).
- Скачивание/доступ — только через проверку прав + сверку тенанта. Path-traversal закрыт (`realpath`/`safeJoin`).
- Воркер берёт только задачи своего тенанта; REST идёт на токене правильного портала.

**Секреты:**
- `B24_APP_SECRET` / ключи только в `.env` (в `.gitignore`); нет хардкода и попадания в транскрипт.
- В логах нет auth-заголовков, тел с токенами, содержимого экспорта (email/имена) — только счётчики и id.
- Per-tenant ключи внешних сервисов хранятся зашифрованно (AES-GCM, AAD = тенант).

**Privacy / 152-ФЗ:**
- ONAPP*UNINSTALL* каскадно удаляет ВСЕ данные тенанта.
- Автоочистка артефактов по retention.
- Нет автоматических рассылок/экспортов без явного запроса пользователя.
- EULA + Privacy доступны статикой; канал обращений субъектов ПД указан.

**Надёжность интеграций:**
- Таймауты на всех внешних вызовах; retry только на transient; 429 → Retry-After.
- Fail-closed на критичных операциях; rate-limit на каждом мутирующем маршруте.
- API request logging >= 3 суток (требование Marketplace).

## Формат вывода
Таблица: пункт / pass-warn-fail / доказательство (`файл:строка`). В конце — список fail/warn с конкретными правками и приоритетом. Резюме на русском для пользователя.
