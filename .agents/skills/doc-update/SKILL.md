# /doc-update — синхронизация доков с кодом

Цель: не дать доке разойтись с кодом в той же сессии.

## Шаги

1. **Что изменилось.** `git diff --name-only` + при необходимости `git diff` по затронутым файлам.
2. **Сопоставь с триггерами** (таблица в `AGENTS.md`):
   - REST-клиент / интеграции → секция «Интеграции».
   - Модель прав / auth → секция «Модель прав».
   - Хранилище / миграции → секция «Хранилище».
   - Маршруты / роутер → секция «Маршруты».
   - Frontend → секция «Frontend».
   - Новый хук / skill / разрешение → README комплекта Codex.
3. **Предложи точечные правки.** Для каждого расхождения: файл доки + что именно поменять (старое → новое). Не переписывай доки целиком — только дельту.
4. Если контракт API/прав изменился — это обязательная правка, не опциональная.

## Правила
- Доки — это разрешённая без согласия зона (см. протокол в `AGENTS.md`), но крупные структурные переписывания сначала проговори.
- Не дублируй один факт в двух доках (`AGENTS.md` = всегда-правда, `WORK.md` = сейчас).
