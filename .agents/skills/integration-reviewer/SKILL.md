# /integration-reviewer — аудит внешних интеграций

Аудит кода, вызывающего внешние сервисы, на надёжность и безопасность. Только чтение + отчёт.

## Чеклист на каждую интеграцию

**Таймаут:** у HTTP-клиента явные `connect_timeout` + `timeout`; нет вызовов с бесконечным ожиданием; для batch — общий таймаут ограничен.

**Retry:** экспоненциальный backoff (0.5s → 1s → 2s); retry только на transient (5xx/сеть/429), НЕ на 4xx; число попыток ограничено (3–5); на 429 — уважать `Retry-After`.

**Rate-limit:** Bitrix24 REST ~2 req/sec на метод на портал — для >1 запроса использовать `batch`. smtp.bz ~10 req/sec — батчить.

**Multi-tenant:** каждый REST-вызов на токене правильного портала (не чужого); каждый SQL фильтруется по `member_id`; воркер обрабатывает только задачи своего тенанта.

**OAuth:** `access_token` обновляется только на 401 `expired_token` (не проактивно — Bitrix блокирует); `refresh_token` в БД, не в логах; refresh не создаёт гонку при параллельных воркерах.

**Fallback:** fail-closed для экспортов (нет частичных файлов); мягкая деградация для некритичного (списки отделов/источников).

**Обработка ошибок:** ловятся конкретные типы исключений; ошибки логируются с контекстом (метод, статус, тенант, job_id); задача помечается `error` + текст для UI.

**Auth/логи:** credentials из env, не хардкод; нет секретов в логах; API request logging >= 3 суток.

## Формат вывода
По каждой интеграции — таблица: проверка / pass-warn-fail / доказательство (`файл:строка`). Затем — конкретные правки с ссылками на строки. Резюме на русском для пользователя.
