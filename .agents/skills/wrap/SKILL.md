# /wrap — финализация сессии

Цель: чтобы следующая сессия (или другой человек) могла продолжить без потерь. Сессия НЕ закрыта, пока `WORK.md` не отражает финальное состояние.

## Шаги

1. **Что сделано.** Кратко собери, что изменилось за сессию (`git status --short`, `git log` новых коммитов).
2. **Обнови `WORK.md`:** активная задача → её новый статус; что доделать; очередь; замеченные алерты/расхождения; action items за пользователем. Конкретно, с путями и значениями.
3. **Doc-update триггеры.** Пройди таблицу из `AGENTS.md`: если менялись REST-клиент / auth / хранилище / маршруты / frontend — предложи (или внеси) обновления соответствующих доков. Код без обновлённой доки = незавершённая работа.
4. **Память.** Если за сессию всплыл устойчивый факт (решение, грабли, договорённость) — предложи добавить/обновить `docs/memory/<тип>_<тема>.md` и строку в `docs/memory/INDEX.md`. Не дублируй то, что уже есть в коде/доках. Относительные даты переведи в абсолютные.
5. **Отчёт.** Покажи пользователю 4–6 строк: что закоммичено/осталось, что обновлено в доках/памяти, что за пользователем.

## Правила
- Не коммить и не пушь без явного «да».
- Не выдумывай факты в память — только то, что реально подтвердилось.
