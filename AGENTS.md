## Протокол действий (соблюдать строго)

**Без согласия разрешено:**
- Читать файлы, логи, код, конфиги; диагностировать; формулировать анализ и предложения.
- Запускать тесты / статанализ / форматтер локально.
- Обновлять `WORK.md`, `docs/memory/*`, `docs/*`.

**Только с явного согласия пользователя:**
- Правки кода (`src/`, `public/`, `bin/`) и конфигов (`composer.json`, `.env`, `Dockerfile`, `docker-compose.yml`).
- Деплой, `git commit` / `git push`, удаление файлов.

**Всегда пауза и явное подтверждение:**
- Любая команда, удаляющая данные пользователей.
- Изменение модели прав / OAuth-credentials.

**Цикл каждого изменяющего шага:**
анализ → вывод/гипотеза → предложение словами → согласие пользователя → реализация → проверка (тест/curl/логи) → отчёт. Этапы не пропускать.

## Ключевые принципы (адаптируй под стек)

- **Слоистая архитектура (PSR-4):** `src/<Integration>/`, `src/Auth/`, `src/<Domain>/`, `src/Storage/`, `src/Http/`, `public/`, `bin/`, `var/` (runtime, не в git).
- **Multi-tenant by design:** идентификатор тенанта (`member_id` / `tenant_id`) во ВСЕХ таблицах; каждый запрос фильтруется по нему. Cross-tenant leak = **Critical** security bug.
- **Секреты только из env** (`.env` в `.gitignore`; `.env.example` — шаблон). Никогда не писать секреты в команды, попадающие в транскрипт; не логировать auth-заголовки/тела.
- **Fail-CLOSED** для критичных операций (упал batch → задача `error`, частичный результат не отдаём).
- **Permission-first:** на каждом мутирующем endpoint — проверка прав ПЕРВЫМ делом.
- **Надёжность внешних интеграций:** таймауты (connect ~5с, total ~30с), retry только на transient (5xx/429/network, не на 4xx), 429 → `Retry-After`, OAuth refresh только на `expired_token` (не проактивно).
- **Тесты-first:** после правок в `src/` — тесты на затронутых файлах. Каждый bugfix → тест на регресс.
- **Документация в той же сессии:** изменил контракт/маршрут/права → сразу обнови соответствующий doc.
- **Диагностика перед отключением:** не выключай проверку/фичу без понимания причины (воспроизвести → гипотеза → проверить → сверить с доками → только потом править baseline).

## Запреты

- Хранение секретов где-либо кроме `.env`.
- Любой endpoint без проверки тенанта в `WHERE`.
- Маршрут без rate-limit.
- Cross-tenant доступ к данным.
- `commit`/`push` на архитектурную задачу без предложения `/premortem`.

## Defaults to challenge (Auto-STOP флаги)

При появлении в обсуждении — остановиться и предложить `/premortem`:
- «Кешировать данные внешней системы локально» → расхождение с реальностью.
- «Автоматический регулярный экспорт/рассылка без запроса пользователя» → privacy-риск.
- «Общий API-ключ внешнего сервиса для всех тенантов» → abuse + cost.

## Эффективность разрешённой работы — урок 05.10.2026

Перед правками запиши в существующем штабе цель, границы файлов и проверяемое
«готово, когда». Уточнение владельца меняет контракт; сам не расширяй предметную
задачу ради попутной уборки. Читай найденный раздел или символ, большой вывод
сохраняй на диск и возвращай краткий итог. Перед запуском сверяй CLI, сигнатуры
тестовых двойников и окружение целевого сервиса. В PowerShell сложный Python
передавай файлом или stdin: кавычки inline -c уже приводили к лишним итерациям.
Закончи правки кода до адресного прогона; полный состав запускай на границе серии.
Повтор успешного состава без изменения входов требует конкретной новой причины;
failed/partial/устаревший результат не заменяет новую проверку. Коммит документов
сам по себе не требует повторения приложения. После проверки родитель читает
машинный итог; запуск, exit 0 и синтаксис отдельно не доказывают непустой результат.
Эти правила дополняют предметные гейты и не заменяют их. Автоматический контроль
не распознаёт произвольное расширение смысла задачи: это часть контракта и ревью.

Это шаблон для новых адаптаций: выбирай собственный штатный runner и его fingerprint/reason. Не копируй часовой пояс, предметные гейты, размеры окна или числовые лимиты другого проекта. Изменяемый исходник обработчика не должен быть единственным активным экземпляром: готовь неизменяемую версию и проверяй её до активации.
